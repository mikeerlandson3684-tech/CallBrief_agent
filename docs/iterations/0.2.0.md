## Goal

Land a **paralyzed** three-column main window whose **card borders follow the PNG layout**, with **every control clickable** (press feedback + a Messages line) around the **already-decided envelope-scaled preview**. Clicks must **not** talk USB, run GRBL, walk a probe cycle, GO TO-move, or write files. Preview Z-circle and grid stay live via the SimulatedPosition stub.

This is the first **new screen** (hence **minor** 0.2.0), not a finished operator app.

## Requirements (Mike)

Locked product decisions that 0.2.0 must **show as controls** (behavior may still be paralyzed). Layout source is the PNG **card borders**, not pixel-perfect chrome and **not** a probe-cycle spec.

### Layout

- Use the mockup **card grouping**: left DRO / GO TO / Status / Jog; center feature / capture / Z / datum / incremental; right preview / Finish / Messages.
- PNG **rounded teal/mint cards** are direction for grouping. Tkinter is the starting toolkit (not a forever look).

### Paralyzed clickable controls

- Every on-screen control shows a press and logs `"{name} pressed"` (or equivalent) to Messages.
- No USB, GRBL, probe walks, GO TO motion, or file I/O from those clicks.

### Preview (already implemented; keep live)

- Always scaled to the **full working envelope** (not zoom-to-part).
- Probe location is a **circle that grows with Z+ and shrinks with Z−**.
- Simple grid; empty file = envelope + grid + probe circle.
- Placeholder envelope (X 0–12 in, Y 0–12 in, Z 0–4 in), not measured travel.
- PNG red concentric glyph is **example coloring, not** the product probe and **not** a cycle spec.

### Locked control intent (labels on the window; cycles/writes later)

| Control | Intent (do not invent the later job in 0.2.0) |
| --- | --- |
| **Capture Feature** | Starts the specified **ID or OD** routine later (prestructured cycle, more than a point). **Do not invent that cycle now.** |
| **Lock Z** | If a Z was captured and many features share that plane, apply it; off → probe must capture Z before writing Z to DXF. |
| **Set DXF Origin** | Drawing datum for the DXF (machine origin and DXF origin can diverge). Not GRBL WCS internals. |
| **Finish Probing** | **Write this data to the DXF** later. Redundant save/export may trim later. |
| **Bridge: COMx** | **Dropped** as a labeled chip. USB itself stays (not in this paralyzed slice). |
| **Hotkeys** | A **window**: click a box associated with a function, then the **next keyboard input or chord** binds that command. |
| **Probe Active** | **Lamp on the computer** when the probe detects a strike. |
| **GO TO** | **Machine coordinates, absolute.** Same target again must not move. Not incremental from current position. |
| **Ctrl+jog** | Control **momentarily** toggles continuous jog to **incremental** jog. Hold Ctrl and give a direction → that step. Unlike GO TO. |

### Hard rules (must not regress)

- **ID circle** and **OD circle** are **separate** routines (not Circle/Rectangle or Inner/Outer as one toggle).
- **No rectangles.**
- **Do not** take probe cycles, walks, or Inner/Outer finder from the PNG. PNG is **not** a cycle spec.
- **Save** and **Close** are already decided and must be **present** (they are missing from the PNG toolbar).
- **Stylus diameter** stays a **hidden-layer tool offset** — **not** a main-screen field.

## Missed / gaps

Particulars **already dictated** that the paralyzed GUI did **not** meet. Taken from mockup vs screenshots and PR 6 source. **Not** a list of new features.

### Rounded teal cards vs Tk

- **Mockup:** rounded white cards, mint header strips, pill-shaped muted buttons, rounded green **Initialized** chip.
- **PR 6 screenshots:** rectangular mint-header panels, raised square `tk.Button`s (`PillButton` is named pill but is `relief="raised"`, `bd=2`). **Initialized** is a green rectangle. DRO axis chips are square frames.
- `digitizer/chrome.py` *approximates* rounded cards on a canvas behind packed frames; the operator-visible window still looks like stock Tk compared with `gui-mockup.png`.

### Hotkeys: click-then-chord not bound

- **Decided:** click a box associated with a function, then the next key or chord (e.g. Shift+P) binds it.
- **Shipped:** stub window, two columns of labels + entries, Close Hotkeys. Clicking an entry logs a press only. No `<Key>` / chord capture, no stored binding. Opening Hotkeys itself is a tab button that logs `"Hotkeys pressed"` (`fixit-clicks.png`).

### Ctrl-hold jog not wired

- **Decided:** Control **momentarily** toggles continuous jog → incremental; **hold** Ctrl and give a direction.
- **PNG copy** (weaker, not the lock): “Ctrl before jog.”
- **PR 6 hint:** “Incremental Jog (hold Ctrl, then jog). Predetermined steps. Not GO TO.” That is still **sequential** (“then jog”), not hold-while-direction.
- **Behavior:** no Control keybind. Jog pad and increment radios only append Messages lines. They do not step `SimulatedPosition` even while Ctrl is held.

### Messages-only clicks

- Messages seed: “Paralyzed GUI — clicks log here. No GRBL, USB, motion, or file I/O.”
- `fixit-clicks.png` transcript is only `… pressed` lines. **Capture Feature** does not start ID/OD. **FINISH PROBING** does not write DXF. **GO TO**, **Home**, **Y+** do not move. **New File / Open / Save / Close** do not touch a file. **Probe Active** click is not a strike. That is the 0.2.0 contract **and** the gap vs locked control intent.

### Incremental / GO TO wording vs lock

- Incremental card documents “Not GO TO” (good).
- It does not implement or even keybind the momentary-Ctrl distinction the lock requires.
- GO TO fields default `0.000` while DRO shows simulated mid-envelope (6.000, 6.000, 2.000 on `paralyzed-gui.png`) — fine for a stub, but sending GO TO still only logs.

### Mockup vs screenshot particulars that are **not** misses

Do not treat these PNG differences as failures; specs already overrode the picture:

- PNG **Circle / Rectangle** and **Inner / Outer** radios — **correctly omitted** (ID/OD separate; no rectangles).
- PNG **Bridge: COM4** — **correctly omitted**.
- PNG toolbar missing **Save / Close** — **correctly added**.
- PNG preview **red concentric glyph** — **correctly not** the product probe; envelope + Z-sized teal circle is the lock.
- PNG **Messages** homing transcript — example copy, not a locked homing walk; paralyzed seed text is appropriate.
- Bottom **Simulated position** sliders + **Empty file / Sample captures** — demo scaffolding so the preview stays live; not on the PNG; not a dictated main-screen product control.
